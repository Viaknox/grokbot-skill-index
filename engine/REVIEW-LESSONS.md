# Engine review lessons

Findings from the PR #12 reviews (Copilot, Codex, Aikido) that came back more than once. Check new engine code against
each row before opening a PR; the test named in the last column guards it.

| Lesson | Why it bit us | Guard |
| --- | --- | --- |
| Everything sent to a remote model goes through the scrubber, including tool schemas and anything a suite file supplies | tool descriptions and enums leaked unscrubbed | `test/codex.test.js` codex 1 |
| A suite file is lower-trust input: it must not choose where your credentials go, run unbounded work, or run arbitrary regexes | `${ENV}` in headers, redirects, `(a+)+` patterns | codex 10, round 2 redirects, round 4 validation |
| Privacy settings are part of a run's identity | `tune` could run with a weaker `--private` list than its baseline | round 4 private identity |
| A completion claim needs a matching, latest, successful action; unclear cases are "unsure", never a pass | lookups, unrelated actions and old successes were accepted as proof | codex 2, round 2-4 claims |
| Unsure verdicts never dilute, hide or inflate a result | unsure diluted failure rates | codex 8 |
| Compare failures by stable identity (case, rule, what was violated, without vote percentages), counted | regressions were masked or invented | round 2/4 regressions |
| Unknown is not zero | http usage printed as 0 tokens | round 4 unknown usage |
| A user turn that is only a bracketed note ("[submitted the hidden field]") is something the bot did for the user, not words they typed: never a repeat or a correction | live Grok Bot test flagged "you had to ask again" | `test/codex.test.js` "bracketed placeholder turns" |
| Secrets are found by their setting name too, not only by known value shapes (any name holding key/secret/token/password/credential) | `AWS_SECRET_ACCESS_KEY=…` reached the judge | `test/codex.test.js` "credentials named like…" (viaknox PR #14, Aikido) |
| A privacy promise is enforced in the request, not left to account settings: every OpenRouter call sends `provider.data_collection: 'deny'` and fails rather than falls back | no-training was only an account setting | `test/codex.test.js` "every OpenRouter call…" (viaknox PR #14, Aikido) |
| A credential is scrubbed whole: PEM blocks header-to-footer, and any setting name that contains a credential word wherever it sits | PEM body and PASSWORD_HASH= leaked | `test/codex.test.js` "whole PEM blocks" |
| Every scrubber regex must run in linear time on hostile input: bounded name, one character class, no nested or overlapping quantifiers; decide "is this a credential" in code, not in the regex | `password-` repeated took 12 s | `test/codex.test.js` "linear time" |
| A privacy scrubber errs toward scrubbing: narrowing a credential rule to avoid false alarms re-opened real leaks four times; over-scrubbed settings are labelled SECRET and only ever "unsure" | PR #14 rounds 1-4 | `test/codex.test.js` "every common form" |
| A credential value runs to the end of its line or field, never to a character count; continuations (`\`, an open quote, a YAML block) go with it | `PASSWORD=` + 200 characters + a suffix leaked the suffix (PR #14 thread) | `test/scrubber-v2.test.js` "known bypass: PASSWORD= plus 200 characters" |
| Placeholders are reserved tokens: nothing re-matches inside one, numbering never collides with placeholder-looking text already in the input, and restore runs in reverse creation order in one pass | a literal `[SECRET_1]` beside a real value made `unscrub` loop forever (v2 integration) | `test/scrubber-v2.test.js` "placeholders: text that already looks like [KIND_n]"; `test/fuzz.test.js` round trip |
| Scrubbing must be idempotent: a value that starts with a placeholder is already done, even with text after it on the line | `"Authorization: [SECRET_1]")` was re-scrubbed into `[SECRET_2]` and ate the `")` (v2 boundary review) | `test/fuzz.test.js` idempotence; `test/scrubber-v2.test.js` "placeholders: scrubbing is idempotent" |
| Never slice or re-scan the whole string inside a per-match callback (`s.slice(0, i).match(/[^
]*$/)` is n² over many matches); use `lastIndexOf` from the match | 8,000 empty `password:` lines took 1.3 s; growth was 4× per doubling (v2 perf suite) | `test/perf.test.js` growth and `password:` ×20000 |
| Credential names are whole parts (split on `_ - .` and camelCase), including plurals and `key` after a qualifier; "starts with a credential word" (`secretary`, `secrete`) is not a credential | `passwords:` YAML lists and `iam-key:` leaked; `secretary:` was blanked (brief item 2, oracle) | `test/scrubber-v2.test.js` "signals" tests; `test/fuzz.test.js` oracle |
| A credential field whose value is an array is a value, not structure; only objects (and arrays of objects) are descended | `"api_keys": ["…", "…"]` leaked both entries (v2 integration) | Phase 3 fixtures `test/corpus/attack-round-*.json` |
| A second mechanism must fail closed: entropy and prefix shapes hold the text back when the main pass misses, and nothing is sent | four review rounds of patching the one regex pass (PR #14) | `test/scrubber-v2.test.js` "residual"; `test/boundary.test.js` held → no fetch |
| Third-party oracle data is only as good as its extraction: store the *value*, not the whole match, or the name's own characters count as leaks | gitleaks `curl-auth-header` samples flagged `Authoriz` as a surviving window (v2 oracle) | `test/corpus/oracle-shapes.json` + `test/fuzz.test.js` oracle |
| Tests that spawn the CLI build its path with `fileURLToPath`, never `URL.pathname` (which is `/F:/…` on Windows) | two tests failed only on Windows (v2 phase 0) | `test/codex.test.js` round 2 and round 4 CLI tests |
| A never-send word in a tool name, a schema property name or a `required` entry cannot be scrubbed (the model must echo them), so the run is refused before any request is built | tool and property names were the one path --private words could still travel (viaknox #25 review) | `test/boundary.test.js` "model adapter refuses a run when a --private word sits in a tool name" |
| The fail-closed residual scan must not fire on text the main pass already scrubbed: blank placeholders with a sentinel, never a space, and never let a shape jump over whitespace into the next token | `--password=[SECRET_1] --api-key=[SECRET_2]` was held because `password=` then skipped to `--api-key=` as its "value" (review round 2 fixtures) | `test/scrubber-v2.test.js` "known bypass (review 2): --password=x…" |
| A sibling pair (`name: password` next to `value: x`) is a credential: the cue and the value live in two fields, in every config and code syntax | Kubernetes env lists, TOML `[[env]]`, annotations and struct tags leaked whole (self-attack round 5) | `test/corpus/attack-round-5.json` |
| A regex `exec` loop that stops on a position check is not bounded in cost: the engine still scans to the end of the text when no later match exists. Remember the last search when matches are visited left to right, or search a slice | 4000 `<textarea name="password">` lines took 1.6 s in the sibling-pair pass (found with the PR #16 review perf payloads) | `test/perf.test.js` "redos: <textarea name=password> x5000" |
| Reserve and exempt only what the scrubber itself mints; a bracketed word of any other kind, and a placeholder with data after it, are values | `password=[ATTACK_1]` and `PASSWORD=[SECRET_1])CorrectHorse9!` passed as "already sanitized" (PR #16 review) | `test/scrubber-v2.test.js` "only real placeholder kinds are reserved", "data trailing a placeholder is scrubbed" |
| Perf budgets are ratios against a baseline measured in the same process, never fixed milliseconds | the 100 ms case took 163 ms on the reviewer's machine and the package's `npm test` failed there (PR #16 review) | `test/perf.test.js` (units) |
| A "credential record" scope must not fall back to "container" because one child is structured; walk it | `credentials:` with a nested YAML map leaked both `username: admin` and the nested `account:` (PR #16 review) | `test/scrubber-v2.test.js` "nested YAML maps, block scalars and lists under a credential key" |
| A variable-length lookbehind (`(?<=\p{L}[ \t]+)`) is a backward scan at every position; bound it, and run the suite on more than one Node version | the growing-indent perf payload took 24 ms on Node 24 and 1.8 s on Node 22, so CI on Linux was red while the build box was green (PR #16 review round 5) | `.github/workflows/test.yml`; `test/perf.test.js` "2000 YAML lines, growing indent" |
